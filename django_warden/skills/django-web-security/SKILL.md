# Django web security

Review the trust boundaries affected by the user's request. Inspect the relevant
settings, data access and templates; do not turn a small change into a full-system
audit. [Web boundaries](references/web-boundaries.md) supplies the detailed checks
and primary sources.

## Workflow

1. Identify the caller, data owner, permitted operation and untrusted inputs.
2. Trace authorization at the actual read/write path, including full/partial
   responses, related form choices, admin actions and download endpoints.
3. Check how data crosses into HTML, JavaScript, URLs, uploads, history and caches.
4. Recommend or implement the smallest authorized correction. Preserve current
   policies; explain a compatibility tradeoff instead of silently weakening them.
5. Test negative access and unchanged state, CSRF with checks enabled, rendered
   escaping and the appropriate browser/header/cache behavior.

## Essential distinctions

- Authentication identifies a caller; object/tenant scope authorizes an operation.
  A hidden control or HX header provides neither.
- A URL linked from Admin is not automatically wrapped by admin_view. Check its
  actual route/decorators, operation permissions and data policy. A path allowlist
  does not require login, and identifying a user in middleware does not authorize them.
- Use Forms/Serializers with allowed fields. Bind ownership from authenticated
  context; validate access to submitted related-object identifiers too.
- Preserve Django autoescaping. json_script helps embed JSON safely but does not
  make arbitrary use of parsed data safe; display text using safe APIs/x-text.
- CSP must match the actual scripts/build. Django 6 has native CSP support; do not
  assume it is enabled, or install an alternative automatically.
- Alpine's CSP build differs from its standard build. Alpine.data alone is not a
  CSP fix. Test the grammar supported by the exact build.
- A nonce is per response. Cache-Control: private only limits shared caches;
  it does not prevent browser reuse. Use an appropriate no-store/never_cache or
  fresh-nonce delivery strategy when required.
- A content type or file extension is not proof of safe content. Combine limits,
  validation, private/quarantined storage and authorized serving as appropriate.
- Secure cookies/HTTPS belong to production deployment context. Consider proxy
  trust and existing settings before changing redirects or HSTS.
- A server test that finds a CSP header does not prove scripts run securely.
  Check real browser behavior; report-only can help a rollout but does not enforce.

Follow the repository's active contract and test runner. Do not weaken governance
checks to hide failures. Missing inspection/browser tools must be reported, not replaced with a
claim of verification. Do not auto-install dependencies or broaden authorization.
LLM prompt engineering is outside this skill; text generated by a model still
needs normal web input/output protections.
